# A terminal UI for the binding REPL, for later

_2026-10-04. Where a short design conversation landed. Nothing is
built. The rustyline fix comes first; this is what we might build after
it, if the REPL turns out to be more than a probe._

## The problem

`bough-repl` prints `watch` output as it arrives, which mixes it into
whatever you're typing. That makes the REPL hard to use once a `tick`
is running.

## The layout we sketched

A ratatui screen with three panes. A full-width input line sits along
the bottom. History takes the left two thirds above it, and Watch the
right third.

```
┌─ History ───────────────────────────────────────────┐┌─ Watch ─────────────────────┐
│ > input n 1                                         ││ n      Int   7              │
│ > tick t 1000                                       ││ fizz   Bool  false          │
│ > def fizz eq (mod n 3) 0                           ││ label  Str   "7"            │
│ > watch n                                           ││                             │
│ > watch label                                       ││                             │
│ > set n x                                           ││                             │
│   ! type mismatch: n is Int, "x" is Str             ││                             │
│ > graph                                             ││                             │
│   n ── fizz ── label                                ││                             │
│                                                     ││                             │
└─────────────────────────────────────────────────────┘└─────────────────────────────┘
┌─ Input ──────────────────────────────────────────────────────────────────────────────┐
│ > def label if fizz "Fizz" (show n)█                                                 │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

The split looks right. Drawing it out raised three questions it
doesn't answer.

## Open questions

**Does Watch show only the current value, or what changed?** `watch`
prints every change today, so you see the sequence. A panel of current
values throws that away, and for the FizzBuzz ticker the sequence is
the point. It also hides the thing we're testing: a panel of latest
values can't show that two redefinitions landed in one instant. Options
are an instant number beside each value (`label "Fizz" @41`), a brief
highlight on change, or a short log of recent changes under the panel.
The instant number is cheapest and is the one that actually tests
`construct`.

**Is History a list of commands or a transcript?** Errors and `graph`
output need somewhere to go. In the sketch they're in History, which
makes it a transcript. That splits "history" into two features: a
scrolling log on screen, and up-arrow recall in the input line.

**Is a TUI worth it yet?** rustyline's `ExternalPrinter` prints above
the prompt without breaking the line being edited. That fixes the
mixed-up output in a few dozen lines. A ratatui UI means owning line
editing, scrolling, focus, resize and terminal restore on panic, and
moving `main.rs`'s `Line`/`Wake` loop onto ratatui's event loop. The
answer depends on what the REPL is for. As a harness for stress-testing
`construct`, rustyline is enough. As the start of an interpreter we'd
actually live in, the TUI earns its cost.

## Where it landed

Do the rustyline version now. Come back to this when the REPL needs to
be more than a probe. The instant number in watch output is worth
having either way, and it doesn't need the TUI.
